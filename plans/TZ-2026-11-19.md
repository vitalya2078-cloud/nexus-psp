# ТЗ: этапы 1–4 (на утверждение)

Каждый этап — отдельная версия: код → тесты в сессии → проверочный APK в чат → проверка на телефоне → следующий этап.
Сервер — Supabase (`kapsula`), всё через edge function с service role, как сейчас. SQL и откат — в `server/sql/`.

## Этап 1 · 0.46.0 — статистика, фон под игру, единый отклик
**Статистика (анонимная, отключаемая)**
- Таблица `events(day date, kind text, k text, n int)` — только счётчики по дням, без кода игрока и без названий файлов.
- События: запуск приложения, запуск игры (консоль), длительность сессии (корзины 0–5/5–30/30–120/120+ мин), падение ядра (консоль), ошибка добавления игры (причина из `Storage.Check`), открытие экранов верхнего уровня.
- Клиент копит счётчики локально и шлёт пачкой при синхронизации (action `stats`); сервер принимает только известные `kind`/`k`, лимит 200 записей за запрос, 1 запрос в 10 мин на игрока.
- Настройки → Общие: «Анонимная статистика» (вкл. по умолчанию, одна строка пояснения). Выкл. — ничего не копится и не уходит.
- Чтение: представление `events_daily` для админки (в «KAPSULA Админ» — экран «Статистика»: DAU, запуски по консолям, падения).

**Фон под выбранную игру**
- На главном экране фон плавно (300 мс) окрашивается палитрой обложки выбранной игры (`pal` уже есть в `Game`), с затемнением для читаемости. Нет игры — текущий фон.
- Без новых картинок, без нагрузки на батарею: один градиент, перерисовка только при смене игры.

**Единые переходы и отклик**
- Одна точка для анимаций (`ui/kit/Motion.kt`): длительности и кривые для открытия экранов, листов, карточек.
- Вибро — только через `Act.buzz*`, три уровня (тап, подтверждение, ошибка), выключатель в настройках уже есть — проверить, что везде соблюдается.

Готово, когда: статистика видна в админке за сутки тестов; выкл. в настройках = ноль запросов `stats`; фон меняется без рывков на слабом телефоне.

## Этап 2 · 0.47.0 — облачные сохранения
- Только сейвы игр: `filesDir/saves/*.srm` и папки PSP `SAVEDATA/<ID>`. Снимки состояния — НЕТ (20–40 МБ).
- Supabase Storage, приватный bucket `saves`, путь `<player_id>/<game_key>/…`; доступ только через edge function (подписанные ссылки на 5 мин).
- Лимит: 20 МБ на игрока, файл до 2 МБ (PSP SAVEDATA пакуем в zip).
- Когда: после выхода из игры (если сейв изменился) и вручную «Сохранить в облако». На новом телефоне после восстановления по коду — «Загрузить сейвы».
- Конфликт (в облаке новее и на телефоне изменён) — спросить: «Оставить телефон / Взять из облака», с датами.
- Готово, когда: сейв переносится на второй телефон через код восстановления; при конфликте ничего не теряется молча.

## Этап 3 · 0.48.0 — недельные испытания
- Таблица `challenges(week, kind, target, reward)`: 3 испытания в неделю. Виды: «наиграй N часов», «сыграй на N консолях», «получи N достижений RA» (только если вход в RA выполнен; иначе это испытание заменяется целью по времени).
- Прогресс считает сервер из данных `kapsula_sync` (время/консоли) и из отчёта клиента о достижениях RA (проверяемый: ID достижения + время, сверка с API RA — если API RA доступен с сервера; иначе без RA).
- Награда — жетоны, забирается кнопкой; учёт в `ledger`, лимит один раз на испытание.
- Админка: задать испытания на неделю или автоподбор из шаблонов.
- Без таймеров «успей» и штрафов (решение от 2026-11-18).

## Этап 4 · 0.49.0 — «Позвать в игру»
- Только одна Wi-Fi сеть (NetPlay по IP уже есть в `Extras.kt`).
- Друг (из списка друзей) получает в «Входящих» приглашение: игра + IP хоста. Кнопка «Присоединиться» — запуск той же игры в режиме клиента с IP.
- Если у друга нет этой игры — понятное сообщение, без попытки скачать.
- Игра через интернет — НЕ входит (нужен свой relay-сервер, отдельная задача).
