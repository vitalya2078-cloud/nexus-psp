### Ограничения, найденные в коде
- Сетевая игра PSP сейчас — по IP в одной Wi-Fi сети (Extras.kt NetPlay). Через интернет — только через ad-hoc сервер, качество не гарантировано.
- Сервер — Supabase (edge function `kapsula`). Облачные сохранения — только сейвы игр (КБ–МБ), не снимки состояния (десятки МБ): иначе упрёмся в лимит бесплатного хранилища.

## 2026-11-18 · Проверка сервера Supabase (только чтение)
- Проект `kapsula` (eu-west-2), 3 игрока, БД 11 МБ. Функции базы закрыты от прямого доступа (anon/authenticated без EXECUTE), всё через edge function `kapsula` с service role — схема правильная.
- RLS включён без политик на всех таблицах — это нормально (доступ только через функции), предупреждения линтера можно игнорировать.
- 🔴 Дыра в `kapsula_sync`: `d_saves` принимается до 1000 за запрос, уровень = (play*2 + saves*30)/1000+1, за уровень +100 жетонов без дневного лимита. Подделанный запрос даёт ~3000 жетонов за раз, бесконечно. Также `d_play` до (минуты с прошлого захода + 60) за запрос — тоже раскачивает уровень. Нужно: лимит d_saves в день, лимит уровней/жетонов за уровень в день.
- Нет ограничения частоты запросов (register, sync) — при росте аудитории стоит добавить.
- Мелочь: нет индексов на admin_log.admin и cheers.from_id (пока неважно).
- Для новых фич нужны новые таблицы: события статистики, облачные сохранения (Storage bucket), испытания.
