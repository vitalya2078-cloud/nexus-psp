## 2026-11-20 · Java-игры (J2ME) — разбор, без кода
Статус: в работе — см. `plans/TZ-J2ME.md`. Решения: вертикально по умолчанию, свои кнопки по макету (клавиатура телефона снизу).
- ❌ SquirrelJME (ядро libretro 0.3.0): мало игр запускается — не берём.
- ❌ FreeJ2ME: нужна Java-машина ПК, на Android не работает.
- ✅ Кандидат: J2ME Loader (github nikita36078/J2ME-Loader, живой, коммит 2026-11-18; форк woesss заброшен с 2023).
  - Лицензии: Apache 2.0; код MicroEmulator — LGPL 2.1 или Apache 2.0 на выбор; sonivox — Apache. ffmpeg-kit (LGPL, очень тяжёлый) нужен только для перекодирования ADPCM-звука — можно заменить своим маленьким декодером.
  - Объём: ~78.6 тыс. строк Java (в 4,5 раза больше всей KAPSULA), 6 МБ нативного кода (3D: M3G, Mascot Capsule; звук MIDI).
  - Устройство: классы J2ME (javax.microedition…) живут в самом приложении; .jar переводится в dex при установке (dexlib, AppInstaller); игра идёт в отдельном процессе :midlet (MicroActivity). Запуск — Config.startApp(name, path).
  - Сборка у них: compileSdk 37, NDK 29, minSdk 21; у нас 35 / 27.2 / 26 — надо выровнять.
  - Тяжёлые зависимости: Room, RxJava, Guava, Volley, CameraX, ACRA, Material — часть выкинуть (камера, отчёты ACRA, их собственный список игр).
- План (предложен): отдельный модуль `j2me/` (их код как библиотека) + KAPSULA сама: библиотека, обложка, запуск, время в игре. Их интерфейс в первой версии — только экран игры и экранная клавиатура.

## 2026-11-18 · Проверка сервера Supabase (только чтение)
- Проект `kapsula` (eu-west-2), 3 игрока, БД 11 МБ. Функции базы закрыты от прямого доступа (anon/authenticated без EXECUTE), всё через edge function `kapsula` с service role — схема правильная.
- RLS включён без политик на всех таблицах — это нормально (доступ только через функции), предупреждения линтера можно игнорировать.
- ✅ ЗАКРЫТО 2026-11-19 (лимиты: игра ≤ времени с прошлого синка и ≤20 ч/сут, сейвы ≤40/сут, жетоны за уровни ≤300/сут, консоли — только из списка, регистрация без переноса жетонов/покупок). Было: дыра в `kapsula_sync`: `d_saves` принимается до 1000 за запрос, уровень = (play*2 + saves*30)/1000+1, за уровень +100 жетонов без дневного лимита. Подделанный запрос даёт ~3000 жетонов за раз, бесконечно. Также `d_play` до (минуты с прошлого захода + 60) за запрос — тоже раскачивает уровень. Нужно: лимит d_saves в день, лимит уровней/жетонов за уровень в день.
- Нет ограничения частоты запросов (register, sync) — при росте аудитории стоит добавить.
- Мелочь: нет индексов на admin_log.admin и cheers.from_id (пока неважно).
- Для новых фич нужны новые таблицы: события статистики, облачные сохранения (Storage bucket), испытания.
